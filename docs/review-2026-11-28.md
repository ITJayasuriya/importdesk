# Inventory validation review — 28 November 2026

Self-review using Ponytail, Thermo-Nuclear Code Quality Review, Interface Design and Better Typography. No independent approval claimed.

## Scope and resolved findings

- One canonical domain validation path now serves both explicit validation and atomic repair commits. Deleted the old presence-only aggregate loop rather than retaining two drifting count implementations. Existing presence issue rules remain shared.
- Duplicate detection uses two cancellable passes and an exact-string count map. Every duplicate member is rejected, including the first; IDs are never normalized, coerced or silently removed. React receives only 50 examples, not the count map or full dataset.
- Calendar rules avoid Date parsing, timezone effects and silent rollover. Gregorian years 0001–9999; YYYY-MM-DD only. Non-ISO strings are DATE_FORMAT, invalid calendars DATE_INVALID. Ambiguous dates remain unchanged pending an explicit conversion workflow.
- Integer syntax accepts an optional minus and canonical decimal digits, including values beyond floating-point precision. No numeric coercion/range inference; whitespace, plus signs, leading zeroes, decimal points and exponent notation are rejected. Identifiers are unrelated string fields and retain leading zeroes. Quantity is an integer, not an invented nonnegative stock constraint.
- Worker request/reply types and all callers now say inventory validation. Revalidation after a missing-ID repair can introduce duplicate errors and is covered end-to-end through the handler. Cancellation, obsolete revisions, immutable source pages and single-use previews remain enforced.
- Existing inventory operator direction retained: source/destination/mapping/exception/preview vocabulary; paper/graphite/blue/amber/green palette, border depth, system controls, monospace raw values, 4px spacing grid. Source provenance and issue table lead; no new dashboard surfaces. Labels explain the rules and limits. h1/h2/h3 descend, body line-height 1.6 and wrapping remain intact; mobile inputs use 16px and raw values use bdi. Actual desktop/360px screenshots inspected. No new design pattern needs a separate system file.

## Evidence and limitations

32 unit tests pass, including leap centuries/year bounds, malformed dates, lexical quantities, all duplicate members, exact string identity, missing/empty counts, repaired views, bounded examples, cancellation in both passes and global revalidation after repair. Local check/build pass; 14 Chromium/WebKit browser cases pass with keyboard, offline, focus, axe, error recovery and preserved source checks.
